# LLM Wiki 운영

출처: Andrej Karpathy, "LLM Wiki" gist (2026-04). 매번 원자료를 다시 읽지 않고, LLM이 관리하는 마크다운 위키를 누적 자산으로 쓴다.

## 세 층

| 층 | 이 저장소에서 | 누가 고치나 |
|---|---|---|
| 원자료 | 코드·`index.html`·사용자가 준 기사·공시 | 원자료로 둔다. 위키 작업 중 고치지 않는다 |
| 위키 | `wiki/*.md` | LLM이 관리 |
| 스키마 | `CLAUDE.md` + 이 스킬 | 사용자와 함께 고친다 |

## 읽기 규칙 (토큰 예산)

1. `wiki/index.md` → 카테고리 페이지 하나. 이것으로 답이 되면 원자료를 열지 않는다.
2. 원자료가 필요하면 페이지의 앵커로 `grep -n` → 해당 구간만 읽는다. 30KB 넘는 파일을 통째로 읽지 않는다.
3. 이력은 `tail -20 wiki/log.md`. 전체를 읽지 않는다.
4. 카테고리를 넘는 작업이 아니면 다른 카테고리 페이지를 열지 않는다.

## 작업

**Ingest** (새 자료가 들어올 때): 자료를 읽고 → 핵심 사실을 해당 카테고리 페이지에 반영 → 기존 내용과 모순되면 페이지에 `> 충돌:` 표시 후 사용자에게 알림 → `log.md`에 한 줄. 한 번에 자료 하나씩.

**Query** (질문): 위키에서 찾아 답하고 출처 페이지를 밝힌다. 다시 쓸 만한 답이면 해당 페이지에 넣는다.

**Edit** (카테고리 수정): 그 페이지의 규칙대로 원자료를 고친 뒤, 앵커·파일·사실이 바뀌었으면 페이지를 고친다. 바뀐 게 없으면 페이지는 그대로 둔다.

**Lint** (요청 시): 페이지의 앵커가 원자료에 실제로 있는지 `grep`으로 확인, 낡은 사실, 목차에 없는 페이지, 페이지 사이 중복을 찾는다. 새로 만들기보다 기존 페이지를 고친다.

## 페이지 쓰는 법

- 한 페이지 = 한 카테고리. 새 카테고리는 `index.md` 표에 한 줄 추가한 뒤에만 만든다.
- 줄 번호 대신 `grep`으로 찾을 수 있는 앵커를 적는다(줄 번호는 매일 바뀐다).
- 원자료에 있는 내용을 복사하지 않는다. 위치와, 원자료만 봐서는 모르는 사실·이유만 적는다.
- `log.md` 형식: `- [YYYY-MM-DD] ingest|edit|lint|analysis | 카테고리 | 한 줄`.
